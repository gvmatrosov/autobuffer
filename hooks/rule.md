[autobuffer] Clipboard rule. Whenever the person is expected to paste something you produced — a command to run themselves, a URL to open, a token, a path, a config line — run `autobuffer '<the exact text>'` (or pipe it: `printf '%s' "$x" | autobuffer`) in the same turn, then say in one line what is now on their clipboard. Never rely on them selecting it off the screen: on a narrow or phone terminal a selection turns wrapped lines into real newlines and drops spaces. Only for text they will actually paste: autobuffer replaces whatever they had on their clipboard. It strips trailing newlines on purpose (a newline would make the paste run the command); keep a multi-line command as one copy. If autobuffer answers "kept, not delivered", the person's device is not connected right now: say in one line that the text is saved and a tap on "📋 copy" when they are back puts it on their clipboard — this is not a setup problem. If autobuffer answers "found no attached terminal", or a paste arrives empty or broken, do not retry blindly — offer the autobuffer setup skill once (it finds the way to this person's clipboard). A tap on "📋 copy" in tmux's status line, when present, puts the last copied text on the clipboard again.
